# v33 轻量化：索引缓存与判定熔断

本版不改变任何判定口径，只减少"每一步都要付一次的固定开销"。改动集中在两处热路径。

## 1 资源索引按目录签名缓存

`preStep` 每一步都会调用 `buildResourceIndex(catalogPool)`——它要读取并分解目录里每个技能的 `SKILL.md` 与参考文件；在 90 个以上技能的目录里，这是每步最重的一次 I/O。

现在按"名字 + 描述"的签名缓存索引：

- 签名不变且未超过 **10 分钟** ⇒ 复用缓存，不重建；
- 目录变化（新增/删除技能、改描述）⇒ 签名变化，立即重建；
- 缓存为空（首次）⇒ 必建。

注意边界：若只改了某个 `SKILL.md` 的正文而名字与描述不变，索引在 10 分钟内仍是旧的。这是用"新鲜度换固定开销"的刻意取舍。

## 2 判定层熔断

`DSH_SKILL_GATE_JUDGE` 默认开启时，每轮都要调一次 LLM 判定（超时上限 8 秒）。判定超时本身已降级为词法兜底，但下一轮还会再等一次。

本版加熔断：同一会话**连续 2 次判定超时**后，**5 分钟内不再调用 LLM 判定**，直接用词法兜底；任意一次判定成功即清零恢复。熔断期内的路由 trace 会标 `judge-timeout-banned`。

## 不改的部分

回答闸的默认值仍为 `off`（v32）；R1–R9 的判定口径、R4 的会话级读取证据、R8 的 `irrelevant`、策略 last-good 回退、目录快照 fail-open 均不变。

## 验证

全量 `node --test --import ./_test/resolve-stub.mjs`：**145/145 通过**（bundle 与安装副本各自就地跑）。两处改动均不改变测试断言的可观察行为。

## 迁移须知

- 升级需重启宿主；运行中的进程仍持有旧模块。
- 版本：`VERSION = 33`，`package.json = 0.5.0`。
