# v31 稳定性与可靠性硬化

本版不改变路由与门控的判定口径，只处理"闸门自身出错时把宿主拖死"的四类故障，以及一条可见噪声。v27/v28/v30 文档是历史设计；涉及这些行为时以本文为准。

## 1 回答闸的自身降级不再写入正文

`stream-limit`（流缓冲超时、字节/分块上限）属于闸门**自身**降级，不是答案的缺陷。v30 之前会把它拼成 `[回答闸] 类型=缓存降级 | 命中=timeout …` 追加到回复末尾；本版改为只写审计与 trace，正文不再出现该提示。其余三类 issue（数字无出处、分母缺证据、不可用缺失败证据）照旧显示。

## 2 读取证据改为会话级

R4 的用户语义是"没读过 / 读过但内容已被改动 ⇒ 拒绝写操作"。v30 的实现按**轮次**记读取，路由每注入一批新候选就清空，导致同一份参考文件在长会话里被反复整读。本版改为**会话级**：键仍是 `<绝对路径>#<内容 sha256>`，因此文件内容一变，旧证据自然失效；只是不再因为"开了新一轮"而失效。

## 3 R8 豁免理由增加 `irrelevant`

路由偶尔会把与当前命令无关的技能列为候选（例如对一条进程状态查询注入基准测试类技能）。此前只能借用 `covered_by` 或 `user_waiver` 表达"无关"，语义不实。本版允许 `SKIP <skill> reason=irrelevant`，并把拒绝文案改为按策略里实际允许的理由动态渲染，避免提示与实际校验不一致。

## 4 策略文件损坏不再让所有工具调用被拒

此前 `DSH_SKILL_GATE_POLICY` 指向的文件一旦出现 JSON 语法错误（实测：手工正则替换多出一个孤立逗号），每次 `tools/pre-execute` 都会抛出解析异常并被折算成 `依从闸：…` 拒绝，等于把宿主锁死，且提示里没有可操作信息。

本版行为：

- 解析成功 ⇒ 记下 **last-good**；
- 解析失败但存在同路径的 last-good ⇒ 按 last-good 继续执行，并写 `policy-stale` 审计；
- 解析失败且无 last-good ⇒ 拒绝，但提示明确写出"策略无法解析（原因）"与文件路径；
- 策略缓存按 `mtime:size` 失效（5 秒），文件一改就重读，不会把旧策略缓存过久。

## 5 技能目录快照失败退化为不路由

`ctx.skills.snapshot()` 抛错时，v30 会让整个 `preStep` 失败。本版包一层 try/catch：取不到目录就当作空目录，不注入候选、不建索引、不写路由账本，宿主继续正常工作。

## 验证

- 全量测试 `node --test --import ./_test/resolve-stub.mjs`：**145/145 通过**（其中 4 条断言按"会话级读取 + 自身降级不写正文"的新语义更新）。
- 独立脚本验证策略两条分支：首次即坏 ⇒ `deny`；同一实例先读好策略再改坏 ⇒ 走 last-good 并写 `policy-stale` 审计。
- 安装副本 8 个 `lib/*.js` 均通过 `node --check`。

## 迁移须知

- 插件在宿主启动时加载，**升级后需重启宿主**才生效。
- 若看到"依从闸：策略无法解析（…）"，按提示修好策略文件即可恢复；期间不会因为该错误而锁死其它工具（有 last-good 时按旧策略继续）。
- `VERSION` 常量为 `31`，`package.json` 版本为 `0.3.0`。
