# v28 分级回答闸

范围：只改本仓库源码、离线测试、文档和验收日志；不执行 refresh.ps1，不部署 profile，不改用户全局配置，不 push/publish。VERSION=28，package.json 包版本保持原值。v27 文档和既有资料保留。

## 发布行为

`answerGateMode` 读取 `DSH_ANSWER_GATE=block|warn|off`，默认 block，兼容旧值 0=off。管理员总开关和 kill switch 继续生效。

| 情形 | block（默认） | warn | off / 本次免检 |
| --- | --- | --- | --- |
| 明确计数缺工具出处，例如“通过 116 项” | 替换文本块并逐项解释 | 保留正文，末尾提示 | 原样放行 |
| 明确全称比较，例如“全部相同”，缺可溯源分母 | 替换文本块 | 保留正文，末尾提示 | 原样放行 |
| 整体能力否定，例如“所有接口不可用”，缺不同方法的失败 | 替换文本块 | 保留正文，末尾提示 | 原样放行 |
| 孤立数字、年份、普通“一致/全部”、局部接口不可用 | 保留正文，末尾提示 | 保留正文，末尾提示 | 原样放行 |
| 代码、行内代码、路径、日期、版本常量中的数字 | 豁免 | 豁免 | 原样放行 |
| 超时或超长 | 降为 warn 流式放行，末尾提示检查未完成 | 同左 | 原样放行 |

这些分类是词法启发式，并非事实性的语义判定器。明确计数目前包括数字后接列/条/链/项/个/次/%/字节/byte/test，以及计数/数量/总数/通过/失败/耗时后紧接数字。未识别的计量写法只告警。

`guardAnswerStream` 同时检查 live delta 与 assembled text。硬拦截在原文本块索引处替换首个文本块，其他文本块留空，工具块逐个保留，避免索引空洞。所有分级均不因回答闸删除工具调用；工具执行本身仍受其他闸控制。重写时保留 finish reason、usage，移除不再与正文对应的 finish replayState。未触发规则时原始 chunks 保持不变。上游 error/aborted 与抛错保持原有恢复/错误语义。

提示逐条生成，例如：

```text
[回答闸] 类型=数字无出处 | 命中=116 | 片段=通过 116 项 | 建议=标[未验]或补工具输出
```

提示会包含原文片段，因此硬拦截表示拒绝把原文作为正常正文发布，并不提供保密或敏感内容过滤保证。

## 证据与格式

`collectAnswerEvidence` 使用请求中全部 tool-role 输出，不按用户轮数截断；用户、assistant 自写内容和调用参数不能提供数值出处。`createAnswerGateState` 用 sessionId 隔离的 LRU 缓存保留已观察结果，以支持后续请求历史被截短的情况。默认每会话最近 1000 条结果，可用 `DSH_ANSWER_GATE_MAX_RESULTS` 设为正整数，上限 10000；会话数量沿用插件 ledgerMaxSessions 配置，非法值回退 128。无 sessionId 时只用当前请求证据，也不提供免检。重启、会话 LRU 淘汰后，未重新出现在请求中的证据不再可用。旧 `DSH_ANSWER_GATE_RECENT_TURNS` 被替代。

数字保留完整 token 比较、国际数字归一化和逐数 `[未验]` 标记。代码围栏、行内代码、绝对或 ./ ../ 路径、日期、v 前缀版本、三段版本及“版本号/VERSION”常量有独立掩码。独立年份等有歧义数字告警，不执行整段硬拦截。

分母接受 `分母=N`、`分母:N`、全角符号、`N 列/条/链/项`、`N/N 相同/一致/通过`、`共 N 项中的 M 项`。可放在本段或紧邻上一段；后段或隔段不解锁。分母本身须在工具输出命中。[未验] 不代替分母证据。

失败方法仍须由当前用户轮真实 assistant tool-call 与 `tool.isError===true` 配对产生。三件套为工具名、实际命令或路径、失败输出首个非空行前缀（最多 160 字符），均出现在断言同段；无需稳定 call id，`[失败证据:id]` 可选。局部接口不可用有一个匹配方法即可；整体能力否定需两个不同方法。成功输出、匿名失败、旧轮失败和同方法重试不能满足整体否定。普通“没有改文件”不再触发不可用规则。

一次性免检只检查最新真实 user/goal 消息的明确指令，例如“本次免检”“请本次免检”“不用闸”；注入提醒、否定和引用不授予免检。同会话缓存存续期间只消费一次，只放行一个 loop-owned 模型请求，不放行整轮多个模型步骤，也不关闭其他工具闸。无持久化存储，重启/LRU 淘汰后额度会重置。

## 缓存与时限

默认缓存最多约 1 MiB 序列化 chunk 数据 / 10000 chunks，默认 2000ms，`DSH_ANSWER_GATE_TIMEOUT_MS` 可设正整数，上限 60000ms。上限判断可超出一个入站 chunk；单个超大 chunk 仍由上游提供，无法从插件内部限制其分配。

期限从 guard 开始消费计算，包含等待上游 stream promise 或 next()。到期立即释放已缓存块，后续直接 yield，不再积累候选缓存；正在等待的 next() 被复用，防止并发读取或丢块。末尾提示缓存降级及检查未完成。没有上游首块时，插件无法制造正文；上游永远不结束时，也无法提前给出真正的末尾提示。取消和上游错误继续传播。audit 为不阻塞的 best-effort，不会因审计慢或失败卡住回答。

## 验证与能力边界

回归覆盖：分级、工具块与结束原因保留、会话历史扩展/隔离/LRU、代码/路径/日期/版本豁免、宽松分母/上一段、失败三件套与反例、live/final 双面检查、超时/缓存降级、模式与一次性免检，并通过注册 hook 做集成验证。验收命令和最终汇总见 validation-v28-tests.log 与 validation-v28-check.log；所有计数按 Node test runner tests 汇总项统计。

最终验收（2026-10-17）：

| 命令 | pass | fail | skip | 分母 tests | 退出码 |
| --- | ---: | ---: | ---: | ---: | ---: |
| npm test | 127 | 0 | 0 | 127 | 0 |
| npm run check | 不适用 | 不适用 | 不适用 | 语法检查，不计 tests | 0 |

`npm test` 同时报告 cancelled=0、todo=0；`git diff --check` 退出码 0。回答闸相关测试共 32 项（26 项模块测试、6 项 hooks 集成测试），其余既有测试 95 项，共 127 项。

- 数字存在不能证明语义对应，不绑定对象、单位、时间或算术关系，echo 出来的数字也会成为词法证据。
- 分母不能证明逐项比较完成；两次失败不能证明全部替代路径均不可用，工具名/命令/失败首行共现也不证明主题对应。
- 代码、路径、日期和版本豁免减少误伤，同时允许错误常量绕开数字检查；语法伪装、引文、未来计划、复杂 Markdown、数词及未列举措辞仍可能误报或漏报。
- 会话缓存只保留插件观察到且尚未淘汰的结果，结果按条数封顶，单条证据文本不另设字节上限；没有新增持久化证据库。
- 退化为 warn 后不再对剩余流执行完整证据检查。兼顾即时展示与发布前全量检查需要这个明确取舍；本次没有生产延迟或内存基准。
- 离线 tests 使用宿主导出的最小替身，不能代替真实宿主 UI 验收。v28 尚未部署；用户已反馈的 v27 生产拦截经历不算 v28 验证。
