# v30 可靠性修复

本版处理回答闸破坏工具消息尾部、流式延迟、取消挂起、证据缓存和判定结果校验问题。v27/v28 文档是历史设计，涉及这些行为时以本文为准。

## 工具消息与回放

当一次模型响应包含工具调用时，插件不再追加机器生成的文本块。警告进入审计；原始工具块、调用编号、结束原因继续传递。该规则同时覆盖 warn、block 降级、字节上限、chunk 上限及超时路径。block 仍可替换工具调用之前的违规文本，但保留工具块。对纯文本响应追加提示时移除不再与块数相符的 native replayState，交给宿主走其 provider-neutral 历史序列化路径。

本机事故记录包含真实 tool/result。损坏发生在 assistant 消息的工具块之后被加上“缓存降级”文本，随后请求被服务端以 tool_use/tool_result 顺序错误拒绝。两个受影响的 v4 日志已在保留原压缩文件备份后，仅移除对应的合成提示；用户消息、工具参数、工具输出和旧错误记录保留。

## 流式与取消

warn 模式即时传递上游 chunk，只保留有上限的审计副本。完整候选结束后检查 live delta 和 assembled text；若超出上限只记降级。包含工具调用的流不追加尾部提示。block 保留缓存检查机制及超时放行，默认 2000ms 和 1MiB/10000 chunks。

等待 stream promise、next() 和超时降级后的 next() 均与用户取消信号竞争。取消时移除插件监听器，清理异常不会覆盖原始错误。适配器无视 AbortSignal 时，插件能退出自身等待，但无法代替适配器终止其网络连接。

## 有界证据索引

回答闸缓存数字集合、结果编号和摘要，不再缓存完整工具正文。相同编号且摘要相同的完整结果复用数字解析；内容改变时失效。预算优先分配给最近结果。截断不会把半个数字当作证据；任一证据丢失或截断均把缺证据判断降为 warn，避免缓存预算造成硬拦截。会话销毁时释放索引；LRU 淘汰仍可能导致证据遗失。

| 设置 | 默认 | 含义 |
|---|---:|---|
| DSH_ANSWER_GATE_MAX_RESULTS | 1000 | 每会话结果条数上限 |
| DSH_ANSWER_GATE_MAX_CHARS | 262144 | 每次索引的工具文本字符预算；也限制会话所保留数字 token 的字符总量 |
| DSH_ANSWER_GATE_MAX_RESULT_CHARS | 65536 | 单条结果的解析字符上限 |
| DSH_ANSWER_GATE_MAX_NUMBERS | 8192 | 每次索引和会话保留的数字 token 总数上限 |

上述是内容、条数限制，并非 V8 总内存字节上限。输入历史已由宿主持有，插件仍需遍历传入消息；未对宿主已有历史、网络流或插件其他模块作总内存承诺。单条流式入站 chunk 也由上游分配。

## 路由与提示

回答闸说明按会话和模式去重，避免每轮重复追加。模式变化或状态被释放后可重新提示。技能判定器支持 promised stream；用户已取消时不再启动调用，忽略取消的适配器也不能让插件一直等待。非空但全是畸形条目的 skills 数组按无效输出处理，走已有兜底；合法空数组仍表示 none。

这些检查仍是词法规则。数字出现不证明语义支持、对象对应或算术正确；未匹配词形、引用和未来计划仍可能误报。默认 block/warn/off 规则未被改成事实正确性保证。实际生产体验仍应结合宿主会话观察，离线测试不能代表云端服务验收。
